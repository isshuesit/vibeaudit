Method

VIBEAUDIT automates the checkable portion of a Trust–Security Gap analysis. Everything below is derived from a single static fetch; nothing is inferred.

What this measures

Whether a page is served over HTTPS, whether it links a privacy policy, which of five security response headers are set, and whether specific text patterns associated with trust inflation appear — confidence-sounding percentages, unverified performance claims, third-party launch badges, testimonial language, manufactured urgency, guarantee and superlative-authority phrasing.

The gap score

Both subtotals are normalised to 0–10 against the maximum the automated checks could produce, then combined as (UTST_norm − SPC_norm) × (1 + HRI). HRI is never inferred — until it is set with the control on the report it stays at 0, so the headline figure is the raw trust / security gap. Bands: Low < 2, Moderate 2–5, High 5–8, Severe ≥ 8.

What it does not measure

Visual professionalism, iconography quality, feature-attribution highlights, and habituation risk require a human eye and are not scored automatically. A high UTST subtotal or gap is a signal worth checking by hand, not a verdict.

Blank-page results are findings, not failures

If a page returns almost no visible text, this tool does not execute JavaScript to render it. That is treated as data: the app relies entirely on client-side rendering with no fallback content for anything reading it non-interactively.

Redirects and connection downgrades

HTTPS is scored on the final URL after redirects. A request that starts on HTTPS but lands on HTTP is flagged as a downgrade and scored as not secure.
